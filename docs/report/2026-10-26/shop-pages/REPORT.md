## Перевірки

- **Chrome:** усі чотири сторінки на 320, 360, 480, 640, 768, 900, 1023, 1024, 1280, 1440 і 1920 px — 44 перевірки адаптивності. Горизонтального скролу немає.
- **Edge, Firefox, WebKit:** кожна сторінка на 360 і 1440 px — 24 перевірки. WebKit є тестовим рушієм, це не перевірка на реальному iPhone/Safari.
- **Консоль / Network:** в основних прогонах немає помилок JS, невдалих завантажень або відповідей, відмінних від HTTP 200. Спрайти, зображення й локальні шрифти завантажуються.
- **Поведінка:** меню відкривається/закривається, Esc повертає фокус; меню профілю також закривається по Esc. Галерея й кількість працюють; кошик перераховується та має порожній стан. Форми показують помилки, фокусують перше неправильне поле, не виконують POST-запитів. Підтвердження пароля перевіряється. Без JS кнопки надсилання Checkout/Account вимкнені.
- **Сценарій:** Product → Cart → Checkout; `account.html#orders` відкриває розділ замовлень.
- **Стійкість:** 12 додаткових перевірок чотирьох сторінок на 360/768/1440 px з дуже довгими назвами/повідомленнями та навмисно зіпсованими зображеннями — без горизонтального скролу. Для зображень є текстові заглушки.
- **Регресія:** Home, Login, Signup, 404 додатково відкриті на 360/1440 px, перевірені ресурси, консоль і мобільне меню — 8 перевірок. Їхні файли залишилися побайтово незмінними.
- **Пункт 12:** один h1, унікальні title ≤65 і description ≤160, alt, підписи полів, defer, відсутність `<style>` та повторюваних id перевірено. Посилання, якорі та регістр шляхів, включно з `Icon-return.svg`, перевірено.
- **W3C Nu:** вихідний HTML і DOM після JS усіх чотирьох сторінок, а також DOM форм Checkout/Account з помилками — **10 перевірок, 0 помилок і 0 повідомлень**. Результати `validators.json`.
- **Jigsaw:** сторінка сервісу відкривається, але POST із новим CSS двічі повернув **HTTP 500** (JSON і SOAP). Результат CSS-валідатора не отримано; успішну валідацію CSS не заявляю. Старі CSS не змінювалися. Інструкція ручної перевірки нижче.

Під час роботи виправлено: ширину колонок Cart на планшеті, центрування фото схожих товарів на телефоні, локальний якір переходу до вмісту, якір розділу замовлень, три зауваження Nu (ролі для підписаних груп і `autocomplete="address-line1"` для однорядкової адреси). Останні три виправлення семантичні, геометрію не змінюють; DOM повторно отримано в браузері та перевірено Nu.

## Прийняті рішення та межі версії

1. Готова Home не отримувала нових посилань або поведінки: це пряма вимога користувачки. Нові сторінки відкриваються за власними адресами. Підключення їх до Home — окреме майбутнє погодження.
2. Шапка/футер повторюють Home, включно з українським текстом, наявними файлами шрифтів і п’ятьма пунктами навігації. На нових сторінках додано надану іконку акаунта, меню профілю та посилання на новий кошик.
3. Усі потрібні фото та іконки взяті з наданих локальних ресурсів. Нові gamepad WebP — без втрат: пікселі RGBA побайтово рівні PNG; оригінали залишено. Доказ `source-audit.json`. Логотипи оплати взято з наданого SVG, а не намальовано.
4. У Checkout виправлено відповідність назв картинкам: в оригінальному PNG назви монітора й геймпада переставлені. Демонстраційні ціни в гривнях узгоджені з уже готовою Home; білий товар на Product має макетну ціну 192 ₴. Серверного каталогу поки немає.
5. Розмір XS–XL збережено як у макеті (опис стосується покриття контролера); це поки візуальний вибір, він не означає реальну наявність варіантів.
6. Сторінка Product представляє один білий геймпад. Інші назви в кошику не перенаправляють на неправильний товар, а показують повідомлення наступного етапу. Промокоди, обране, соціальні мережі, адресна книга та способи оплати також мають повідомлення-заглушки.
7. Меню акаунта містить профіль, замовлення і вихід; повернення/відгуки з додаткового макета не реалізовано окремими функціями в межах цих чотирьох сторінок. Вихід поки повідомляє про наступний етап, адже справжнього входу ще немає. Бічні пункти Account з основного PNG збережені.
8. Оплата карткою вимкнена, збережено її місце й логотипи; основний вибір — оплата при отриманні. Чекбокс збереження даних є за макетом, але не зберігає контакти в цій демонстрації.
9. Поля Account заповнені навчальними прикладами. Кнопка збереження тільки перевіряє їх; паролі очищуються після успішної перевірки. Реальний профіль, зміна пароля та історія замовлень потребують майбутнього API.

## Як перевірити локально

1. У папці `web-practice` запустити вже наявний `start-server.bat`.
2. Відкрити `http://127.0.0.1:8000/web-practice/product.html`.
3. Інші адреси: той самий початок + `cart.html`, `checkout.html`, `account.html`.
4. Перевірити фото, вибір параметрів, кошик, форми й мобільне меню. Почати варто з Product → «Купити зараз» → Cart → Checkout.
5. Для початкового демонстраційного кошика відкрити сторінку в новій вкладці без успадкованого сеансу або очистити тільки ключ `exclusive-layout-cart-v1` у Session Storage. Персональні дані цей ключ не містить.

Не відкривати HTML подвійним кліком через `file://`: браузер може блокувати зовнішній SVG-спрайт. Нові сторінки поки не опубліковані; для їх перегляду потрібна ця робоча гілка.

## Jigsaw вручну

1. Відкрити [CSS Validator](https://jigsaw.w3.org/css-validator/), вкладку **By file upload**.
2. Вибрати `web-practice/assets/css/shop-pages.css`; профіль CSS level 3, medium all; натиснути Check.
3. Зберегти скриншот підсумку та, якщо є, рядків помилок/попереджень у цю папку. Помилки/непідтримані сучасні властивості треба розібрати окремо, не приховувати зміною готової Home.
4. Для повного набору стилів можна окремо завантажити `_variables.css` і `style.css`; вони побайтово ті самі, що в попередній прийнятій версії.

Реалізацію зупинено на верстці й локальній демонстрації. Публікація, зміни Home та підключення сервера/бази потребують наступної команди.
