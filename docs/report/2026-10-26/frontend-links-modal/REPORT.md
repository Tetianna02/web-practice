# Модальна форма та зв’язування сторінок

Дата: **26.10.2026**. Гілка: **stage2-shop-pages**. Початковий коміт: `7277b6c`. Робота обмежена фронтендом; сервер і база не підключалися. Злиття в `main` не виконувалося.

## Що змінилося

| Файл / група | Зміна |
|---|---|
| `product.html` | Кнопка «Запитати про товар» та діалог із трьома полями: ім’я, email, запитання |
| `assets/css/product-question.css` | Окремі стилі тільки для Product: діалог, затемнення фону, поля й кнопка відкриття |
| `assets/js/product-question.js` | Відкриття/закриття, керування фокусом, виклик спільної валідації, повідомлення після успіху |
| Усі 8 HTML-сторінок | «Про нас» веде до переваг магазину на Home (`#services`), «Контакти» — до контактної колонки Home (`#contacts`); посилання акаунта й кошика ведуть на готові сторінки |
| `index.html` | Іконка кошика й відповідний пункт футера ведуть на `cart.html`; «Мій акаунт» — на `account.html`; «Купити» у JBL-банері — на `product.html`; додано тільки id контактної колонки |
| `assets/js/main.js` | Кнопки купівлі та іконки перегляду динамічних карток Home відкривають `product.html`. Напис кнопок карток узгоджено з дією: «Купити» |

Кнопка запитання розміщена у вже наявному вільному проміжку під блоком товару. Вона не зсуває галерею, опис, доставку або схожі товари. Основні CSS `style.css`, `auth-pages.css`, `shop-pages.css`, `_variables.css`, іконки, картинки та шрифти залишилися побайтово незмінними.

Окремих About і Contact не створено: навігація використовує змістовні наявні розділи. Налаштування приватності, обране, соцмережі, Google-вхід та інші ще не реалізовані можливості залишають чесне повідомлення наступного етапу. Посилань на неіснуючі HTML-файли немає. Product поки представляє один демонстраційний товар; завантаження різних товарів із каталогу належить наступному етапу API.

## Модальне вікно: як перевірити

1. Відкрити `/web-practice/product.html`, натиснути **«Запитати про товар»** під блоком доставки. Фокус переходить у поле імені, фон стає недоступним для взаємодії.
2. Натиснути «Надіслати запитання» без даних: під усіма трьома полями з’являються українські повідомлення; фокус — на першій помилці.
3. Заповнити ім’я та запитання, ввести некоректний email: форма залишається відкритою й указує помилку email.
4. Ввести коректні дані: діалог закривається, з’являється повідомлення **«Форму перевірено. Запитання не надіслано — демоверсія.»**
5. Окремо перевірити закриття хрестиком, натисканням на затемнений фон та Esc. У кожному випадку фокус повертається на кнопку відкриття.
6. Tab і Shift+Tab залишають фокус усередині відкритого діалогу. Після закриття поля й помилки очищуються; повторне відкриття показує чисту форму.

Використано нативний `<dialog>` та спільний `Shop.validate`. Потрібні непорожні поля; перевіряються формат email та мінімум 2 символи імені. Є `label`, `name`, `required`, `autocomplete` для імені/email, пов’язані повідомлення помилок. Натискання всередині форми не закриває її. Дані не потрапляють у URL, мережеві запити або сховище застосунку.

## Як відкрити й пройти сценарій

Запустити наявний `start-server.bat`, відкрити `http://127.0.0.1:8000/web-practice/`. Натиснути «Купити» на картці або у JBL-банері → Product → «Купити зараз» → Cart → «Оформити замовлення» → Checkout. Посилання в шапці й футері відкривають Login, Signup, Account і кошик; «Про нас» та «Контакти» відкривають відповідні розділи Home.

Це локальна статична демонстрація. Після push вона залишається в робочій гілці. Публічний GitHub Pages не оновлюється цією роботою: користувачка самостійно перевірить гілку й виконає PR/merge, коли буде готова. Справжні повідомлення, авторизація, каталог із БД і запис замовлень не є частиною цього завдання.
