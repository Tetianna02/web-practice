# Як самостійно повторити перевірку

Доступ до обох сервісів отримано, тому ручна перевірка **не є незавершеною обов'язковою дією**. Нижче — інструкція для захисту або якщо викладачу потрібні скриншоти саме вебінтерфейсу валідаторів.

## W3C HTML

1. Відкрийте [Nu HTML Checker](https://validator.w3.org/nu/).
2. Виберіть перевірку через завантаження файлу, завантажте `web-practice/index.html` і запустіть перевірку.
3. Зробіть скриншот, на якому видно адресу сервісу, назву/спосіб перевірки та підсумок без помилок. Назва: `w3c-source-ui.png`.
4. Так само по одному завантажте фінальні HTML із папки `web-practice/docs/report/2026-10-25/step-5/dom/`: `chrome-rendered.html`, `edge-rendered.html`, `edge-menu-open.html`, `edge-modal-register.html`, `edge-modal-login.html`.
5. Це вже знімки сторінки після JS, тому валідатору не потрібно виконувати скрипт. Збережіть скриншоти з відповідними назвами `w3c-...-ui.png`.
6. Не використовуйте `dom-before-dynamic-fix/`: це навмисно збережений стан до виправлення рейтингу.

Поточний очікуваний результат кожного з шести файлів — 0 помилок і 0 попереджень. Якщо сервіс оновиться й покаже інше, збережіть новий результат повністю, не приховуйте повідомлення.

## Jigsaw CSS

1. Відкрийте [Jigsaw CSS Validator](https://jigsaw.w3.org/css-validator/), вкладку завантаження файлу.
2. У додаткових параметрах виберіть профіль CSS3 + SVG, усі типи носіїв і всі попередження.
3. Перевірте окремо `web-practice/assets/css/_variables.css`, потім `web-practice/assets/css/style.css`.
4. Збережіть скриншот загального підсумку кожного файлу та повного списку восьми діагностик style.css. За потреби зробіть кілька знімків із прокруткою: `jigsaw-variables-ui.png`, `jigsaw-style-summary-ui.png`, `jigsaw-style-errors-ui.png`.
5. Не приховуйте помилки/попередження. Поточний підсумок: змінні — 0/0; style.css — 8 діагностик, позначених сервісом як errors, і 771 warning. Пояснення у REPORT.md; зелений статус style.css не заявляється.

## Console і Network у браузері

1. Запустіть `start-server.bat`, відкрийте `http://127.0.0.1:8000/` у Chrome, а потім у Edge.
2. Натисніть F12. На вкладці Network очистіть журнал і перезавантажте сторінку; прокрутіть до футера, щоб завантажилися відкладені фото.
3. Перемкніть усі слайди, відкрийте/закрийте меню та форму, виконайте пошук і скиньте його. У Network не повинно бути 4xx/5xx або failed. Збережіть скриншот і, за потреби, HAR.
4. На Console перевірте відсутність червоних помилок. Інформаційний запис Edge про lazy-loading допустимий і вже описаний у звіті. Збережіть Console окремо для кожного браузера.
5. Повторіть за ширин 360 і 1440 px. Перевірте favicon у звичайній вкладці браузера. Знімки зберігайте в цій папці з назвою браузера, шириною та датою.

Адреса localhost із сервера 8000 — для вашого перегляду. Автоматизована серія використовувала окремий сервер 4173 і префікс `/web-practice/`; його HAR-журнали збережені в step-5. Публічний сайт ще не створено.
