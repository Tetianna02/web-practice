# GitHub Pages: дії власниці

Дата підготовки: 25.10.2026. Репозиторій: [Tetianna02/web-practice](https://github.com/Tetianna02/web-practice). Він уже публічний. API GitHub повернув `has_pages: true`: налаштування можуть уже бути правильними, тому спочатку перевірте їх.

1. Увійдіть у GitHub своїм обліковим записом і відкрийте репозиторій за посиланням вище.
2. У верхньому меню репозиторію натисніть **Settings**. Якщо вкладку не видно, перевірте меню з трьома крапками. Це налаштування репозиторію, а не профілю.
3. У лівому меню знайдіть **Pages** (секція Code and automation).
4. У **Build and deployment → Source** виберіть **Deploy from a branch**.
5. У **Branch** виберіть **main**, поруч — **/(root)**, і натисніть **Save**, якщо значення змінювалися. `/(root)` означає головну папку репозиторію, де лежить `index.html`. Папку `/docs` не вибирайте: там звіт, а не головна сторінка.
6. Дочекайтеся завершення розгортання. На вкладці **Actions** має успішно завершитися Pages build/deployment; у **Settings → Pages** з'явиться повідомлення про публікацію й кнопка **Visit site**. Це може тривати кілька хвилин.
7. Відкрийте **Visit site**. Очікувана адреса — [https://tetianna02.github.io/web-practice/](https://tetianna02.github.io/web-practice/). Власний домен не потрібний. Якщо доступний прапорець **Enforce HTTPS**, залиште його ввімкненим.
8. Напишіть агенту фактичну адресу, яку відкрила кнопка. Після цього він перевірить публічну Home, ресурси, меню, модалку, консоль/Network і PageSpeed Insights окремо для mobile та desktop. До цього крок 6 залишається незавершеним. Оптимізації — лише після вашого дозволу.

Для GitHub Free Pages працює з публічними репозиторіями; цей репозиторій уже відповідає умові. Публічні файли, включно зі звітом, можуть бачити інші люди. Сайт наразі є frontend-демонстрацією: майбутні авторизація, замовлення та backend ще не реалізовані.

Джерела: [вибір гілки й папки публікації](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [створення Pages і доступність на GitHub Free](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## Якщо push попросить авторизацію

Не надсилайте пароль чи токен у чат і не вставляйте їх у файли. Git на цьому комп'ютері налаштований на Git Credential Manager. За потреби запуск звичайного `git push` у вашому терміналі може відкрити вхід через браузер: увійдіть у **Tetianna02** і підтвердьте доступ саме для Git Credential Manager. Якщо замість браузера бачите помилку, передайте текст помилки без секретних даних. Після входу push можна повторити; повторний клон чи новий репозиторій не потрібні.

Точний результат автоматичного push буде повідомлений окремо; цей розділ сам по собі не підтверджує успіх.
