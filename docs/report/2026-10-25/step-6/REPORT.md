## Зміни для публікації

- Додано порожній `.nojekyll` у корінь. GitHub Pages за замовчуванням використовує Jekyll, який виключає файли з початковим `_`; Home потребує `assets/css/_variables.css`. Маркер вмикає публікацію звичайних статичних файлів без обробки Jekyll. [Офіційна інструкція](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
- Додано `.gitignore` для локальних `.env`, залежностей та службових файлів ОС; `.env.example` може бути окремим безпечним шаблоном у майбутньому.
- Оновлено README та додано [просту інструкцію власниці](PAGES_GUIDE.md).

HTML/CSS/JS і вигляд Home на цьому кроці не змінювалися. Чотири незафіксовані ресурси майбутніх сторінок залишено поза комітами: auth-hero, icon-google, login/signup PNG. Усе потрібне саме Home вже відстежується.

## Розмір звіту

Перед додаванням Firefox/WebKit відстежувані файли мали приблизно **44,06 MiB**, із них `docs/report` — **36,10 MiB**. Повторний аудит після додавання браузерних доказів і підготовчих документів: **339 файлів, 49,04 MiB**, із них звіти — **41,07 MiB** (значення на момент знімка JSON, до наступних невеликих доповнень звіту). Це переважно докази попередніх ітерацій, вони не завантажуються під час звичайного відкриття Home і не збільшують її Network-передачу.

Пропозиція на майбутнє: після прийняття всього етапу зібрати старі HAR і дубльовані PNG в архів, прикріпити до GitHub Release, а в репозиторії залишити підсумкові результати та актуальні знімки. **Нічого не видалено й не перенесено.** Видалення файлів окремим комітом не прибере їх зі старої історії Git; переписування історії — окреме рішення, зараз воно не потрібне.

HAR тут створені локально без реальної авторизації; тіла відповідей у браузерному аудиті виключені. Для майбутнього backend не можна публікувати HAR із cookies, токенами або персональними даними.

## Що залишається

1. Push підготовлених комітів у `origin/main` (фактичний результат повідомляється після виконання).
2. Власниця перевіряє Settings → Pages: Deploy from a branch → main → /(root), повідомляє адресу.
3. Перевірка саме публічної версії: іконки, шрифти, картинки, меню, модалка, консоль, Network.
4. PageSpeed Insights mobile/desktop, збереження результатів і пояснення причин оцінок. Зміни продуктивності лише після дозволу.
5. Підсумковий коміт кроку 6 після цих перевірок і очікування «далі».

Локальний аудит не видається за підтвердження доступності публічного сайту. Відомий формат URL не замінює запитане підтвердження власниці.
