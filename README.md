# Exclusive — навчальний магазин

## Як відкрити сайт на Windows

1. У папці `web-practice` двічі натисніть `start-server.bat`.
2. Не закривайте вікно, що з'явиться: у ньому працює локальний сервер.
3. Відкрийте в браузері **http://127.0.0.1:8000/**.
4. Після змін у файлах оновіть сторінку через **Ctrl+F5**.
5. Коли закінчите, закрийте вікно сервера або натисніть у ньому **Ctrl+C**.

Якщо адреса вже працює після повторного запуску, користуйтеся наявним вікном сервера. Не потрібно запускати кілька копій. Якщо порт 8000 зайнятий іншим застосунком, повідомте про це.

Для запуску потрібен Python 3; на поточному комп'ютері він уже встановлений. Файл сам перевіряє `py -3`, потім `python`. Нічого завантажувати під час запуску не потрібно.

Не відкривайте `index.html` подвійним кліком для перевірки сайту. Такий спосіб дає адресу `file:///...`; браузер може блокувати зовнішній SVG Sprite. Через `http://127.0.0.1:8000/` HTML, стилі, шрифти й Sprite отримуються з одного локального сервера. Це лише сервер перегляду frontend, не майбутній backend курсової.

## Шляхи для GitHub Pages

Очікувана адреса проєкту має префікс `/web-practice/`. У Home використані відносні шляхи `assets/...`, а CSS завантажує шрифти через `../fonts/...`. Вони працюють і з кореня локального сервера, і з префікса GitHub Pages. Зовнішній Sprite доступний за `/web-practice/assets/images/icons/sprite.svg` після публікації всіх ресурсів.

Публікація на GitHub Pages ще не виконувалася; локальна перевірка префікса не означає, що сайт уже доступний в Інтернеті. Покрокове ввімкнення Pages — окремий крок 6.

## Локальні шрифти

Типографіку бережемо за поточним `assets/css/style.css`; нових сімейств, ваг і розмірів під час виправлення сервера/скролу не вводимо. Google Fonts не використовується.

| Шрифт | Вага | Локальний WOFF2 | Де використовується |
|---|---|---|---|
| Poppins | 400 | `poppins-regular.woff2` | Базовий текст, латинські фрагменти меню, підписи, iPhone 14 Series |
| Poppins | 500 | `poppins-medium.woff2` | Назви товарів, ціни, кнопки й посилання, частина заголовків футера |
| Poppins | 600 | `poppins-semibold.woff2` | Кількість відгуків, числа круглого таймера, виділені написи |
| Poppins | 700 | `poppins-bold.woff2` | Підключений; збережений для запитів ваги 700. Основні поточні жирні заголовки задані Inter |
| Inter | 100–900 доступні; у Home потрібні переважно 400/500/600/700 | `inter-latin.woff2`, `inter-cyrillic.woff2` | Hero, заголовки секцій, логотип, лічильник; українські літери у стеку Poppins → Inter |

У наявних Poppins немає українських літер, тому вони вже відображаються локальним Inter із тією ж запитаною вагою. Це наявна поведінка шрифтового стека, не нова заміна шрифтів. Латинський і кириличний файли Inter підключені через `unicode-range`.

## Горизонтальна прокрутка

Причиною переповнення була ширина стрічки розпродажу, розрахована через `100vw`: це значення включало системну вертикальну смугу прокрутки. Секція тепер є контейнером для вимірювання ширини, а стрічка використовує `50% + 50cqw`. Її правий край доходить до реального краю контенту, а внутрішня прокрутка товарів зберігається. Для браузера без підтримки цього розрахунку залишається безпечна ширина 100%.

## Що пояснити на захисті: крок 3

CSS Sprite — це одне зображення з кількома іконками. У `service-icons-css-sprite.svg` об'єднані три наявні іконки переваг: доставка, підтримка та захист. CSS задає фон і його положення, щоб кожний елемент показував лише свій фрагмент. Контури іконок збережені з оригінальних SVG. Решта іконок продовжує використовувати наявний SVG Sprite через `<use>`.

Таймери рахують час до конкретного моменту, заданого в HTML атрибутом `data-countdown-end`, а не від першого відкриття сайту. Демонстраційний строк обох акцій — **31.01.2027 о 23:59:59 за Києвом** (`+02:00` для цієї дати). Перезавантаження не починає акцію заново. Після строку замість таймера з'являється «Акцію завершено». Для зміни строку треба оновити також пояснювальні `aria-label` і `title` у відповідному блоці.

Кошик, обране та відсутні сторінки показують повідомлення «Буде доступно на наступному етапі». Форма входу/реєстрації перевіряє поля лише у браузері й пояснює, що серверну авторизацію ще не підключено. Обліковий запис поки не створюється.

## Що пояснити на захисті: мобільна версія

Mobile First означає, що початкові стилі працюють для вузького екрана. Через `min-width` до них додаються правила для ширших екранів. У Home використані пороги 480, 640, 769, 1024 та 1280 px. Велика версія за макетом вмикається з 1280 px: нижче фіксованим колонкам футера не вистачало місця разом із бічними відступами й системною смугою прокрутки.

На телефоні каталог — горизонтальна стрічка в один ряд, а кнопку «До кошика» видно без наведення. На планшеті видно більше карток; до 1024 px навігація, пошук і категорії містяться в burger-меню. Усі стрічки прокручуються всередині своїх блоків, не розширюючи сторінку. Для фото товарів використовується `object-fit: contain`; великі індивідуальні розміри з desktop обмежені широким екраном.

У відкритому меню Tab не переходить на приховану фоном сторінку; Esc, кнопка закриття й клік на фоні закривають меню. Модальне вікно зроблене через HTML dialog; фокус переходить на видиме поле, після закриття повертається до кнопки відкриття, а на низькому екрані прокручується сама форма.

Після переглядів оновлено всі три стрічки, кадрування новинок, планшетний iPhone та центрування JBL. Актуальний звіт і скриншоти: `docs/report/2026-10-25/step-4/revision-3/REPORT.md`. Попередні версії збережені як історія. Емуляція екрана у браузері не замінює перевірку на фізичному телефоні чи в Safari.

Розміри стрічки обчислюються за формулою `(доступна ширина − (кількість видимих карток − 1) × проміжок) / кількість видимих карток`. На телефоні закладено 1,75 картки, на 768 px — три. Стрілки переміщують на одну або дві картки, стають disabled на краю; зазвичай приховані, якщо все вміщується. Виняток за вимогою макета: у каталозі від 1024 px пара завжди видима, а при вміщенні обидві кнопки disabled. Клавіатура: Tab до стрічки, ліворуч/праворуч, Home/End. Смуги приховані; пальцем працює звичайна прокрутка браузера зі scroll-snap.

«Знайдіть те, що потрібно» теж є стрічкою: до 1024 px один ряд, від 1024 px два ряди з чотирма видимими колонками. Більша кількість товарів додає колонки праворуч. Перші чотири товари лишаються зверху, наступні чотири — знизу, як у макеті; фільтр перераховує цей порядок для відповідних товарів. На desktop стрілки завжди видимі та гортають до чотирьох колонок. «Усі товари» показує toast майбутньої сторінки каталогу. Дозавантаження по 8 скасоване. Популярні товари залишаються окремою сіткою, обмеженою чотирма картками.

Висота каталогу зарезервована для одного/двох рядів і не росте від кількості товарів, включно з порожнім списком. На 1440 px збережено початкові висоти рядів 322/350 px та проміжок 60 px. На 768 px iPhone збільшено з 320 до 416 px (+30%); окремі колонки тексту й фото розділені щонайменше 12 px. Розмір обмежується доступним місцем, тому на 640–1023 px фото не накладається на текст.

На телефоні й планшеті всі плитки новинок мають висоту 240 px; колонки та парфуми масштабуються окремо через contain. Їхні фото розташовані праворуч, текст — унизу ліворуч із градієнтом. Широкий desktop зберігає попередні розміри й розташування фото.

До 1024 px JBL має спільну центральну вісь для підпису, заголовка, чотирьох круглих таймерів, кнопки й фото. Проміжок після кнопки — 16 px. У квадратному PNG є великі прозорі поля; CSS показує всю видиму область колонки 1166×667 px, прибираючи тільки ці поля. Оригінальний файл не змінений. З 1024 px попередня desktop-композиція збережена; наддовгий заголовок обмежений трьома рядками, щоб кнопка залишалася в банері.
